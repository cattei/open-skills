# 阶段 `story` — 用户场景（默认由 AI 起草，人审核后才往下走）

> 本地新增阶段（非上游 spec-kit）。对应文件：`stories.md`。
> 方法论：`../../references/xp-ai-acceptance.md` §5；实例：`Project-IngredientAnalyzer/规划/用户故事-买菜帮手.md`。

## 默认模式（不指定内容时）

用户只发 `/spec-kit` 或 `/spec-kit story`，**不需要**先说场景。你的动作是：

1. **扫材料**：`0项目集规划/总规划.md`、`总执行.md`、目标的 `规划/` 目录、`docs/`、README、代码里的页面/路由、已有截图与文案。
2. **起草 3–6 条用户场景**（能覆盖主要角色与主流程即可，不要贪多），每条按模板写：口述、页面要素、待确认。
3. **标来源与置信度**：每条故事下面注明依据（哪份文档/哪个页面/哪段代码），猜测的部分写 `⚠️ 我按 X 推断`。
4. **交人审**：输出一份"待审清单"（见下），**停下等用户改文件**，不许直接进入 `impact`。
5. 用户改完回来说"可以了"，才继续。

用户直接口述也照样支持：口述 > 扫出来的材料，冲突时以口述为准。

### 待审清单（产出后必须给）

```text
我起草了 4 条用户场景，写在 specs/001-xxx/stories.md，请你直接改文件（改完告诉我）。
- U1 王大姐买醋  依据：规划/00-总索引.md；⚠️ 首页按钮文案是我按代码推断的
- U2 李哥买水果  依据：选水果模块文档；✅ 有现成截图佐证
- U3 孙小妹买化妆品  依据：宣传/推文；⚠️ 上传入口位置不确定
- U4 ……          依据：无，我编的——**请确认这条要不要，或者你来讲真实场景**
需要你决定的 3 件事：①… ②… ③…
```

## 审核纪律（用户会人工改）

- **文件是唯一真源**：用户改完的 `stories.md` 覆盖你起草的一切；后续一律以文件内容为准。
- **不覆盖用户的修改**：再写这个文件前先读；只补空着的段落，或按用户明确指令重写。发现用户改的和代码矛盾，指出来，别偷偷改回去。
- **不许替用户确认**：`⚠️ 待确认` 只有用户能消；他确认一条就把标记改成 `✅ 用户确认（日期）`。
- **审核没过不写 spec**：`stories.md` 里还有 `⚠️ 待确认` 的核心项时，`specify` 阶段只列问题，不落笔。

## 执行步骤

1. **判断输入**
   - 用户直接口述场景 → 走"记录"路径（见下）；
   - 只给项目名/一句话 → 走"默认模式"起草；
   - 已有 `stories.md` → 先读，问是补、改还是重写。
2. **采访**（口述路径，一次问一组，别一口气问 10 个）：
   - 谁：这个人是谁、什么场景下用（"王大姐，去小卖部买醋"）
   - 从哪进门：怎么打开、首页看到什么
   - 干了什么：点了/拍了/填了什么
   - 看到什么：**逐项**描述页面（先是什么、再是什么、文案大概是什么）
   - 万一呢：没网 / 拍糊了 / 没权限 / 结果和想的不一样
3. **原话记录**：能贴原话就贴原话，只做分行和编号，不改写成需求术语。
4. **补齐四件事**：入口 / 输入 / 看到 / 万一；缺的进「待确认」（每条 ≤3 项）。
5. **复述确认**：用 1 段话复述"你的意思是……"，让用户点头。
6. **汇总能力清单**（给 `impact` / `plan` 用）。
7. **写文件**：按 `references/templates/user-story-template.md` 产出 `stories.md`；用户审核后进入 `impact`。

## 写法硬约束

| 必须 | 禁止 |
|---|---|
| 标题用「谁 + 干什么」（王大姐去买醋） | 标题写成功能名（"配料识别"） |
| 只写用户看得见的东西 | 出现接口名、字段名、类名、框架、表名 |
| 一条故事一个页面闭环 | 一条故事横跨 5 个页面 |
| 失败/异常也写进故事 | 只写"一路顺利"的理想路径 |
| 起草时标依据与置信度 | 把猜测写成既定事实 |
| 真会发生的场景 | 编造用户画像和不存在的数据 |

## 完成标准

- [ ] `stories.md` 存在，≥1 条 U 编号故事，每条有：口述、页面要素、待确认、实现核对（空表待填）
- [ ] 起草模式下，每条都有依据标注；猜测的标了 `⚠️`
- [ ] 已输出待审清单，并**停下等用户改文件**
- [ ] 用户确认后，能力清单可直接喂给 `impact`
- [ ] 向用户报告：几条故事 / 几条待确认 / 下一步 `/spec-kit impact`

## 给用户的引导话术（口述时可直接粘）

```text
不指定内容也行：你直接说"给 <项目> 生成用户场景"，我会先扫现有规划文档和页面，
起草几条场景到 stories.md，你改完我再往下做（界面影响面、业务流程、验收卡）。

如果你想亲自讲，就照这个说，我按四件事追问：从哪个页面进来、你点/填了什么、
页面上你看到什么、万一出错会怎样。

示范（买菜帮手）：
「王大姐去小卖部买醋，好多种不知道哪个好。她打开小程序，首页有个很大的
『拍一拍，帮你买』按钮，点了对着配料表拍照，就跳到配料表分析页。页面上先给
一个总结：买不买、为什么；然后一张表，一个个解释标准是怎么回事、这个配料干什么的。」
```
