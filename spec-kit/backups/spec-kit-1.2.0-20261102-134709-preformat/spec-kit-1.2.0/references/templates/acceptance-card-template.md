# 验收卡 — <项目名 / 模块名>

> **用途**：把用户故事翻译成"可以逐项打勾"的验收标准。实现前写卡，实现后按卡验收。
> **谁写**：AI 可以起草，**人必须确认**；打勾只能是人的动作或人确认后的动作——AI 不得自己判定"全过"。
> **粒度**：一张卡 = 一个页面 / 一个动作，半小时 ~ 半天。超过半天 → 拆；跨多个业务流 → 拆。
> **铁律**：验收不通过时回到卡片，不是回到代码——先判断是卡片漏写，还是实现错了。

## 验收动作（按顺序，别跳）

1. **①** 打开页面逐项看：有没有、文案对不对、状态对不对；
2. **②** 喂输入：正常 → 边界 → 空 → 异常，四种都要；
3. **③** 点跳转、看联动、看全局状态有没有串；
4. **④** 从头到尾走一遍业务流，包括失败/取消路径；
5. 全绿 → 归档 + 提交（`feat: RAC-001 配料表分析页出结论`）；有差距 → 按下面格式回写。

### 差距回写格式（给 AI 的）

```text
RAC-001 未通过
- ①-3：页面上没有"是否建议购买"的结论块，只有一张表（期望：结论置顶）
- ②-5：断网时白屏，没有提示（期望：提示"网络异常，重试"）
- ④-2：点"返回"后首页品类选择被重置（期望：保留上次选择）
```

> 不要写"不对，再改改"。精确到格、条、实际现象，AI 才能一次改对。
