# 全网真相调查

目标不是堆砌搜索结果，也不是宣告绝对真相，而是给出**可复核、可推翻的当前最佳判断**。

先回答用户最关心的核心问题，再展示依据与边界。不得用“信息很多”“众说纷纭”代替判断，也不得把确定语气当作证据。

## 一、何时启动完整调查

以下情况使用本 Skill 的完整流程：

- 新闻、传闻、爆料或辟谣需要确认真假；
- 不同来源互相冲突，需要判断哪些内容可信；
- 需要还原事件时间线、利益关系或当事人目的；
- 用户要求“深查”“查真相”“交叉验证”“找出核心结论”。

单纯查找一个明确资料时可只执行单次搜索，不必机械生成完整调查报告。

## 二、不可突破的证据纪律

1. **核验对象是主张，不是文章。** 先把大问题拆成可独立判真伪的原子主张。
2. **搜索摘要不是原始证据。** 关键来源能打开正文时必须打开；未打开、无法访问或只有摘要时明确降级。
3. **链接数量不等于独立验证。** 转载、通稿、同一匿名爆料和同一当事人跨平台发言分别归入同一独立来源组。
4. **官方和当事人也不免检。** 一手材料可能只证明狭窄事实，也可能有立场或选择性披露。
5. **主动找反证。** 不得只搜支持自己初步判断的关键词；关键矛盾必须解释或显式挂起。
6. **事实、当事方指控、推断、建议和未知分开写。** 动机、原因和未来预测不能因为听起来合理就写成事实。
7. **搜索工具与 AI 摘要只是线索。** 搜索排序、内置评分、模型摘要和自动交叉验证文本均需重新核对，不直接转换成结论或概率。
8. **无法证实不等于已经证伪。** 使用“证据不足”“存在争议”等状态，不二选一强行判真假。
9. **保护隐私。** 不把用户秘密、私人材料或内部业务数据作为搜索词发送给外部服务。

详细规则见 `references/investigation-method.md`；名人争议、诉讼和动机问题同时读取 `references/public-dispute-motives.md`。

## 三、搜索工具约束：只用 WorkBuddy 原生能力

1. 使用 WorkBuddy 当前会话提供的**原生网页搜索工具**发起查询，使用其**原生网页打开或读取工具**核对关键正文。
2. 不调用任何外置搜索 API、专用搜索接口、Token 或本地搜索脚本；本 Skill 不需要 Python、接口 URL 或凭证配置。
3. 工具名称、参数和调用限制以 WorkBuddy 当前实际提供的工具定义为准，不编造工具或参数。按工具限额分批查询，失败与空结果必须保留记录。
4. 搜索结果只提供线索，不自动完成来源审计或真相判断。能打开正文时必须使用原生读取能力核对原文、上下文和时间。
5. 没有原生搜索能力时，明确说明无法完成实时核验；不得恢复旧接口，也不得假称已经搜索。只有搜索摘要而没有正文读取能力时，关键证据必须降级并写入核验边界。

每次检索至少记录：`query_id / claim_id / purpose / query / searched_at / status`。状态使用“有结果 / 空结果 / 失败 / 待复查”，不能用搜索成功代替主张已核实。

## 四、标准调查流程

### 阶段 0：定义问题与范围

先固定：主体、事件、地域、目标时间、信息截止时间和判断口径。

把用户问题拆成 `C1、C2…` 原子主张。例如“X 起诉 Y 是为了炒作”至少拆为：

- C1：X 所称的法律行动实际处于什么阶段；
- C2：双方各自公开说了什么，原始出处是什么；
- C3：事件发生前后有哪些可核验动作和利益变化；
- C4：哪些事实支持或削弱“炒作”解释；
- C5：还有哪些同样能解释现有事实的替代假设。

主体同名、时间错位、“起诉/受理/判决”等概念不清时先澄清，不用更多搜索掩盖定义问题。

### 阶段 1：建立竞争假设与检索计划

对原因或动机问题至少保留两个真正不同的假设，其中应包含善意或常规解释，并写出可区分它们的观察点：

- 如果 H1 成立，应出现哪些记录或后续动作；
- 如果 H2 成立，哪些材料更可能存在；
- 什么证据会推翻当前最受欢迎的解释。

为每条核心主张安排支持性、反证性和原始出处查询。查询必须随已获得实体名、案号、时间、专业术语和矛盾点迭代，不只重复改写同一句话。

用检索日志管理 WorkBuddy 原生搜索，不再生成脚本批量计划：

| query_id | claim_id | purpose | query | searched_at | status |
|---|---|---|---|---|---|
| Q1 | C1 | 原始出处 / 支持 / 反证 |  |  | 待复查 |

### 阶段 2：分维检索并回到原始出处

使用 WorkBuddy 原生搜索执行检索日志中的查询，并用原生网页读取能力打开关键结果。按问题机制选择信息轴，不机械凑平台数量：

- 主体与背景；
- 行为与结果；
- 关系与利益；
- 专业规则与时效；
- 独立第三方与反方；
- 事件时间线与异常信号。

优先追溯公告、法院或监管记录、原始数据、完整采访、原始视频和当事人原文。只有转载时标记“未回到原始出处”。

### 阶段 3：建立主张—证据关系

每条关键证据至少记录：

- `evidence_id`、标题、URL、发布主体、作者；
- 事件发生时间、原始发布时间、抓取时间；
- 原文摘录及必要上下文；
- 对应 `claim_id`，支持还是反驳；
- 直接/间接证据，S/A/B/C 来源层级；
- `independence_group` 及同源判断理由；
- 是否实际打开正文、适用范围和访问限制。

来源层级只决定审查优先级，不直接裁决真假。评估“这条材料能否证明这个主张”，不给某个媒体或人物设置永久可信标签。

### 阶段 4：矛盾与反证检验

主动搜索否认、撤稿、纠错、处罚、败诉、反方证据、旧版与新版差异及不适用边界。

发现矛盾后先分类：定义、时间、范围、数据、利益或真正事实冲突。不得靠多数表决、情绪强度或模型自信消除矛盾。

### 阶段 5：形成核心结论与动机解释

每个结论使用完整推理链：

> 因为 E1、E2，在前提 A1 下更支持 H1 而非 H2；但缺口 G1 未闭合，因此当前结论为……，置信度为……。

动机分析必须回答“通过该行动可能获得什么”，同时列出：

- 可观察的收益、成本、时间点和实际后续动作；
- 至少一个替代解释；
- 每个解释的支持证据、反证和缺口；
- 哪种新证据会改变当前排序。

只有身份标签、既往争议、单方指控或“谁受益”时，不生成确定的动机结论。当事人公开声称的目的只证明其如此宣称。证据足以比较时，可写“最符合当前材料的解释”；证据不足以区分假设时，明确不做动机排序并写“无法判断”，不能宣称读取了当事人真实内心。

### 阶段 6：回溯复查与输出审计

形成初步结论后，用新获得的实体、时间、案号、术语和矛盾点回查。环境支持独立审阅者时，让其专门攻击最脆弱的推断；没有独立检索的第二意见只能审逻辑，不能增加事实。

输出前逐项检查：

- 核心结论是否有对应主张和证据；
- 关键引用是否实际打开并确实支持该主张；
- 是否去掉伪多源并完成反证搜索；
- 是否保留未解决矛盾、证据缺口和证伪条件；
- 是否区分事实、当事方指控、推断、建议与未知；
- 是否核对主体、时间、地域、单位和事件阶段；
- 是否全程使用 WorkBuddy 原生搜索与读取能力，未调用旧接口或虚构检索结果。

任一关键项失败，返回对应阶段补证据或降低结论等级，不只润色措辞。涉及名誉的对外成稿，增加人工复核后再发布。

## 五、结论状态与停止条件

使用以下状态：**已证实 / 较可信 / 部分成立 / 证据不足 / 存在争议 / 已被推翻 / 已过期**。

置信度只用有解释的“高 / 中 / 低”或“较可信 / 中等 / 低置信”。没有统计基础时不编造精确概率。

满足以下条件之一可停止：核心主张证据充分且新增搜索只重复同源材料；决定性原始材料已完成时效与反证检查；关键证据经合理路径仍不可得并已降级；达到约定成本上限并交付阶段性结果。

不得因为找到三篇相似文章、模型语气确定或隐藏了核心矛盾而停止。

## 六、最终交付

按 `references/report-template.md` 输出。标准报告至少包括：

1. 问题与范围；
2. 一句话核心结论及置信度；
3. 已确认事实、当事方指控与事件时间线；
4. 可信、存疑、已证伪信息及逐条理由；
5. 来源独立性与“伪多源”说明；
6. 动机/利益的竞争假设、当前排序或无法排序的理由；
7. 矛盾、反证和证据缺口；
8. 证伪条件与值得跟踪的信号；
9. 可采取行动与暂不应采取行动；
10. 核验边界及关键来源链接。

每条核心主张必须使用统一字段：`claim_id / status / evidence_ids / counterevidence_ids / scope / confidence / gap / falsifier`。

即使证据不足，也要明确交付“目前能确认什么、哪些解释仍有可能、是否足以排序、为什么不能更进一步”，不能只给用户一堆链接。
