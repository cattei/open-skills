# 从信息洪流到可验证的真相
## 复杂信息核验 Skill 设计说明

**版本**：设计草案 v1.0  
**整理日期**：2026-10-28  
**用途**：供后续制作复杂 Skill，不是可直接运行的脚本，也不承诺任何调查都能得到确定真相。  
**方法定位**：信息核验 / 证据审计 / 矛盾驱动的真相研究。

---

## 一、这份文档从哪里来

### 1. 检索范围

本次实际检索了原始对话库、结构化记忆和已有的方法笔记，找到两条直接相关的讨论脉络：

- **2026-09-03 原始讨论**：孙永乐提出，面对散落各地的信息，应该去哪里找、哪些是不同维度的关键信息、如何综合相关性、真实性和实时性，以及“每一步怎么验证是否通过”。
- **2026-10-13 方法总结**：从一次具体核查中提炼出六层纵深研究法，后续纳入现有 `truth-finder` 与 `contradiction-truth-research` 方法。

同时参考了同期已经固化的证据分级、独立性去重、回溯复查和外部第二意见规则。

### 2. 原始讨论中最值得保留的思想

当时形成的不是“多搜几个网站”的技巧，而是一套认知方向：

1. **真相是一个极限值，不是手里那份材料。** 信息只能用来逼近它，不能把暂时搜到的内容当作真相本身。
2. **信息 = 维度。** 每个维度是一条独立证据轴；单一维度再丰富也不等于完成交叉验证。
3. **验证 = 对抗。** 查自己的记忆、查第三方来源、查互相矛盾的地方，再让外部智能体做反方复核。
4. **矛盾感是信号，不是噪音。** 不一致说明仍有未被理解的机制、遗漏的条件或错误前提，不能靠多数表决压下去。
5. **结论要带反证条件。** 不只说“我认为是什么”，还要说“什么新证据会推翻它”。

> 本文其余部分是对这些讨论的结构化整理与 Skill 化建议。新增的字段、状态机和工程结构是设计建议，不倒填为用户当时的原话。

## 二、总原则：核验的对象不是文章，而是主张

### 1. 基本目标

输入一条说法、一个传闻、一组互相冲突的材料，或一个“X 看似很差却获得机会”的反常问题，输出：

- 哪些是已有直接证据的事实；
- 哪些是有根据但尚未闭合的推断；
- 哪些仍只是线索、传闻或模型幻觉；
- 当前最可信的解释是什么；
- 还缺哪一块决定性证据；
- 哪些新证据会改变或推翻当前结论；
- 据此可以采取什么行动，哪些行动仍应暂缓。

**默认目标是给出可复核的当前最佳判断，不是宣告绝对真相。**

### 2. 三条不可混用的“通过”

| 通过类型 | 实际证明 | 不能证明 |
|---|---|---|
| **存在性通过** | 确实找到了该来源、文件或记录 | 来源内容必然真实 |
| **真实性通过** | 关键主张有适用的直接证据支撑，并完成反证检查 | 所有相关事件都已查明 |
| **时效性通过** | 资料适用于指定时间、地区、对象和版本 | 资料在当前或所有场景仍有效 |

例如，找到某公司的官网公告，只先通过“来源存在”；公告是否覆盖当前主体、是否已被后续公告修订、公告是否能证明传闻中的全部内容，仍需分别验证。

### 3. 信息、来源、证据不是同一层级

- **信息**：出现过的内容，可能是帖子、转述、数字、截图或模型回答。
- **来源**：信息的承载者及其出处。
- **原始来源**：最接近事件、记录或数据产生的位置。
- **证据**：能够支持或反驳某个具体主张的材料。
- **直接证据**：不需要额外关键推断即可支持该主张的材料。
- **间接证据**：能缩小解释空间，但还需推理才能连接主张。
- **线索**：只用于寻找下一步证据，不进入最终事实层。

**原始来源也可能错误、不完整或带有利益立场；“官方”“一手”“当事人说”都不是免检标签。**

## 三、核心数据结构：先拆主张，再建证据关系

复杂 Skill 不应只围绕“搜索结果列表”运行，应维护四种对象。

### 1. 主张（Claim）

把大问题拆成能单独判真伪的最小可核验命题。

示例：

> “A 公司现在经营正常，B 老板拥有多家公司，所以 A 不会出问题。”

至少拆为：

- C1：B 与这些公司存在可核验的股权或任职关系；
- C2：这些关系在目标日期仍有效；
- C3：相关公司的经营状态如何；
- C4：老板名下其他公司的状况能否支持对 A 的判断；
- C5：“现在正常”具体指工商存续、实际经营、发工资、缴社保，还是现金流健康。

**工商存续不等于实际经营，实际经营不等于没有风险。** 每个词都要指定判断口径。

### 2. 证据（Evidence）

每条证据至少记录：

- `evidence_id`：内部标识；
- `url` / 文件路径 / 原始记录位置；
- 标题、发布主体、作者或机构；
- 原始发布时间、抓取时间、事件发生时间、有效期间；
- 原文摘录及其上下文，而非只有搜索摘要；
- 支持的 `claim_id`，以及支持或反驳关系；
- 来源层级、是否直接证据、适用范围；
- 独立来源组 `independence_group`；
- 原始性或独立性可疑的原因；
- 可访问性、完整性及是否已打开正文。

### 3. 假设（Hypothesis）

当事实不足以唯一确定解释时，并列保留多个假设：

- H1：表面现象所暗示的常规解释；
- H2：有具体机制支持的替代解释；
- H3：有意包装、选择性披露或欺骗；
- H4：混合解释。

不要一开始就给所有假设分配看似精确的百分比。先收集能区分它们的证据，再作相对排序。

### 4. 缺口（Gap）

证据缺口必须能指导下一步行动：

- 缺的是哪条主张的什么证据；
- 为什么现有材料不能替代；
- 可去哪里找；
- 找到后支持或反驳什么；
- 若仍无法获得，最终报告如何降级。

## 四、主流程：从问题定义到可推翻的结论

## 阶段 0：定义问题，而不是立即搜索

### 要做的事

1. 明确用户真正要判断的决策或疑问。
2. 固定时间范围、地域、主体、对象和版本。
3. 把问题拆成原子主张。
4. 区分事实核验、原因解释、预测和价值判断。
5. 判断风险与深度：轻核查、标准核查、深调查。

### 通过闸门

- 能清楚回答“要让用户改变什么判断或行动”；
- 每个核心主张都能单独寻找支持与反驳证据；
- 没有把原因解释或未来预测伪装成可直接核验的事实；
- 主体同名、时间错位、地域错配等歧义已标出。

### 不通过怎么办

缩小问题或向用户确认，不用扩大搜索量掩盖定义不清。

---

## 阶段 1：建立多假设与判别问题

对复杂或反常问题，先列出至少两个真正不同的解释，再列判别问题：

- 如果 H1 成立，应当还能观察到什么？
- 如果 H2 成立，哪种记录最可能存在？
- 哪个事实若出现，会明显削弱目前最受欢迎的解释？
- 用户最怀疑的解释，是否有真实的直接反证？

**通过标准**：不同假设能导出不同的可观察预测，而不是只换几种措辞重复同一解释。

---

## 阶段 2：六维信息轴——按机制找，不按平台凑数

同一问题至少从适用的不同维度寻找信息。以下是研究轴，不是每次必须机械凑满的六项。

| 信息轴 | 主要寻找 | 能解决什么 |
|---|---|---|
| **主体与背景** | 官方登记、身份、机构沿革、规则、基础语境 | 对象是否同一、概念是否用对 |
| **行为与结果** | 真实动作、记录、产品、作品、经营或事件结果 | 主体实际做了什么，而非只说会做什么 |
| **关系与利益** | 股权、合作、资金、转载、上下游、共同利益 | 谁与谁有关，谁可能从某种说法获益 |
| **专业与时间性** | 研究、专业方法、版本、修订、新旧口径 | 判断是否专业、是否过时 |
| **第三方立场** | 独立评价、反方观点、亲历者、受影响者 | 防止只听主体自述或单一叙事 |
| **事件与信号** | 公告、新闻、异常记录、时间线、风险事件 | 还原变化过程，发现孤立材料看不到的异常 |

不同问题应替换维度。例如医疗问题需要临床指南、患者具体情况和禁忌；设备问题需要型号、固件、日志和复现条件。**不要把“公司调查”的六轴硬套所有主题。**

### 通过闸门

- 已覆盖与问题机制相关的关键维度，而非仅完成六个搜索词；
- 每个维度有明确的“已找到 / 没找到 / 不适用 / 无法访问”状态；
- 缺失维度已进入缺口清单，不以其他维度的材料充数。

---

## 阶段 3：来源审计与“伪多源”去重

### 1. 先追原始出处

从二手内容回溯原始公告、文件、数据、论文、演讲、合同或记录。若只能找到转载，要标明“未回到原始出处”。

### 2. 检查独立性，而不是统计链接数

以下情况通常只有一个有效来源组：

- 多篇文章转载同一篇报道；
- 不同自媒体引用同一匿名爆料；
- 集团内不同账号复用同一宣传稿；
- 搜索摘要、AI 摘要和正文都来自同一内容；
- 同一主体在不同平台重复发布；
- 多个模型在没有独立检索时给出相似答案。

### 3. 来源层级只决定优先级，不直接裁决真假

可使用 S/A/B/C 分层：

- **S**：适用范围内的官方文件、法律合同、原始数据库、原始数据、可复现实验；
- **A**：专业媒体、论文、专业机构、有编辑审核的行业资料；
- **B**：有署名、有证据链、能回查的专业分析或亲历记录；
- **C**：匿名帖、无出处转载、内容农场、只有情绪或结论的内容。

注意：

- S 级材料也可能只证明狭窄事实；
- 官方自述对“自己如何评价自己”未必独立；
- B/C 级可以提供线索，不能仅靠数量升级为事实；
- 来源可靠性与主张真实性是相关但不同的字段。

### 通过闸门

关键主张至少做到以下之一：

- 有适用且可检查的直接证据，并完成反证搜索；
- 有两条以上真正独立的证据路径，且不存在更强反证；
- 若做不到，明确标为“单源”“未核实”或“尚无证据”，不能写成已交叉验证。

---

## 阶段 4：矛盾驱动的对抗检验

### 1. 主动找反证

搜索不能只重复支持性关键词，应加入：

- 否认、争议、处罚、失败、纠错、撤稿；
- 相反结果、异常案例、不适用的边界条件；
- 旧版与新版差异；
- 受影响者或反方的具体证据。

### 2. 把矛盾分类，不急于选边

| 矛盾类型 | 处理方式 |
|---|---|
| **定义矛盾** | 两边说的不是同一指标、同一主体或同一口径，先统一概念 |
| **时间矛盾** | 不同时期都可能是真的，建立时间线和有效期 |
| **范围矛盾** | 局部与整体、样本与总体、特定地区与全国不能互推 |
| **数据矛盾** | 回原始数据、计算方法和单位，复算而不是看文章转述 |
| **利益矛盾** | 检查披露、激励和选择性呈现，但不能只凭动机判假 |
| **真正事实冲突** | 比较证据的直接性、原始性、独立性及可复核性，保留未决状态 |

### 3. 矛盾未被解释前，不得静默消除

最终报告必须保留：谁与谁冲突、冲突在哪条主张、目前如何处理、为何仍不足以下结论。

**通过标准**：不是“所有文章观点一致”，而是所有已发现的关键不一致都得到了分类、解释或显式挂起。

---

## 阶段 5：从证据到结论，而不是从结论挑证据

### 1. 每个结论写完整推理链

推荐句式：

> 因为 E1、E2（证据），在 A1（明确前提）下，更支持 H1，而不是 H2；但 G1（缺口）尚未闭合，所以当前结论为……

### 2. 区分事实、推断、建议和未知

- **事实**：有直接、适用且可复核的材料；
- **推断**：由事实经过明确逻辑得到，前提必须写出；
- **建议**：结合风险与目标提出的行动，不冒充事实；
- **未知**：当前无法获得或无法区分的内容。

### 3. 概率用于表达不确定性，不用于制造精确感

可使用“较可信 / 中等 / 低置信”等等级。若使用概率，必须说明是主观校准，不是统计频率；不能把“来源数量”“搜索轮数”或模型自信直接换算成概率。

---

## 阶段 6：回溯复查、第二意见与停止条件

### 1. 回溯复查

结论形成后返回第一维，用已经获得的实体名、时间、专业术语和矛盾点重新搜索。初查时常因不懂语境而漏掉重要资料，复查不是无意义重复。

### 2. 反方复核

优先问外部模型或另一名审阅者：

> “现有证据最支持哪个替代解释？哪个关键推断最脆弱？什么反证会推翻结论？”

不要只问“你同意吗”。第二意见是校验，不是终审；没有独立检索的模型意见不能当成新事实来源。

### 3. 停止不是“搜够了”，而是满足条件

可以停止的情况：

- 核心主张已有足够证据，新增搜索只重复同一来源组；
- 已找到决定性原始材料，并完成必要的时效和反证检查；
- 关键证据经合理路径仍不可得，已将结论降级并列出缺口；
- 达到事先约定的时间或成本上限，明确交付阶段性结果。

不得停止的情况：

- 仅因为找到三条相似文章；
- 仅因为搜索结果开始重复，但重复的都是同一出处；
- 仅因为模型给出了确定语气；
- 核心矛盾仍被隐藏在总结之后。

## 五、结论状态机：避免“不是真就是假”

建议使用以下状态：

| 状态 | 含义 |
|---|---|
| **已证实** | 在明确范围内，有直接且适用的证据支撑，反证检查未推翻 |
| **较可信** | 多条独立证据一致支持，但仍有明确的小缺口 |
| **部分成立** | 主张中只有某些子命题成立，或只在部分时间/范围成立 |
| **证据不足** | 材料太少、太间接或无法核验，不能支持方向性结论 |
| **存在争议** | 有实质独立证据相互冲突，尚无法合理消除 |
| **已被推翻** | 有适用的强反证，或原始主张的必要前提不成立 |
| **已过期** | 曾经成立，但不适用于当前目标时间或版本 |

“辟谣”也必须走相同证据标准。**不能因为无法证实，就直接断言为假；无法证实与有证据证伪是两回事。**

## 六、最终报告的最小结构

1. **问题与范围**：时间、地区、主体、判断口径。
2. **一句话结论**：当前最可信判断及置信程度。
3. **已经确认的事实**：逐条对应证据。
4. **仍属推断的部分**：写出推理链与前提。
5. **来源独立性说明**：哪些看似多源其实同源。
6. **矛盾与反证**：关键反方材料及处理结果。
7. **证据缺口**：缺什么、为什么重要、去哪找。
8. **证伪条件**：什么新证据会改变结论。
9. **跟踪指标**：哪些变化值得复查。
10. **行动成熟度**：现在能做什么、先观察什么、暂时不要做什么。
11. **核验边界**：哪些数据库、原件、当事人或受限资料没有获得。

行动成熟度建议：

- **可立即行动**：依据充分，且行动风险与证据强度匹配；
- **可观察，不可下结论**：保留跟踪，不做高成本动作；
- **暂不可采取行动**：关键事实不清，先补决定性证据。

## 七、复杂 Skill 的推荐编排方式

### 1. 建议采用“一个主控 + 四个角色”

- **主控 / Researcher**：定义主张、安排维度、维护证据表和缺口，不急于写结论。
- **反方 / Adversary**：专门寻找反证、同源关系和替代解释。
- **审计员 / Auditor**：检查每条关键事实是否有证据、时间是否匹配、引用是否真的支持该主张。
- **撰写者 / Reporter**：只根据已审计的证据表输出，不自行补充新事实。

小任务可合并角色，但不能删除反证与审计动作。

### 2. 建议保留的中间产物

```text
调查问题.md            # 范围、原子主张、假设、判别问题
来源清单.jsonl         # 来源、时间、原文摘录、独立组、访问状态
主张证据表.jsonl       # claim ↔ evidence 的支持/反驳关系
矛盾清单.md            # 不一致、分类、处理状态
证据缺口.md            # 缺口、查询路径、影响
调查报告.md            # 只写已审计内容
```

### 3. 必须有环路，不能只是六步直线

```text
定义主张
   ↓
多假设 → 分维检索 → 来源审计 → 对抗检验
   ↑            ↓              ↓
   └──── 补证据/换查询/回到原始出处 ←──┘
                         ↓
                 结论与证据审计
                         ↓
              通过？→ 报告 / 未通过？→ 回到缺口
```

### 4. 工程闸门

在输出前自动或人工检查：

- 每个关键结论是否有 `claim_id` 和对应证据；
- 每个引用是否实际打开并支持原文主张；
- 是否把搜索摘要、转载或模型回答当成原始证据；
- 是否声明了独立来源组；
- 是否至少执行过反证搜索；
- 是否保留未解决的矛盾；
- 是否区分事实、推断、建议和未知；
- 是否列出证据缺口与证伪条件；
- 是否核对时间、主体、地域、单位和版本；
- 是否把“行动建议”误写成“事实结论”。

任何一项失败，都应返回对应阶段，而不是只让撰写者润色措辞。

## 八、两类常见陷阱

### 陷阱 A：做了很多检索，仍然没有验证

症状：搜索词很多、文章很多、报告很长，但关键主张只有转述，没有原始证据。  
修正：回到原子主张与证据表，找出“哪个材料真正证明哪句话”。

### 陷阱 B：把一致性当作真实性

症状：多个平台、多个模型、多个群友都这么说，于是判真。  
修正：追共同上游，检查是否有独立观察、独立数据或独立记录。

### 陷阱 C：用动机分析代替事实证明

症状：因为某方有利益，就认定其说的一切都是假。  
修正：利益关系用于提高审查强度，最终仍需核对具体内容与独立证据。

### 陷阱 D：强行消灭矛盾感

症状：为了交付一个漂亮结论，把不合理解释为“信息有限”，或选择多数一方。  
修正：把矛盾变成下一轮研究的判别问题；必要时保留争议。

### 陷阱 E：为了显得客观而编造概率

症状：没有统计基础却给出“83.7% 可信”。  
修正：使用有定义的置信等级，公开关键缺口；若给主观概率，必须给校准依据与区间。

## 九、与其他能力协同时的边界

- **记忆检索**负责“我们以前说过什么、当时依据是什么”，不自动证明旧时结论仍正确。
- **实时搜索**负责获取新资料，不自动完成来源审计。
- **专业计算与复现**负责核验数字、代码、实验和逻辑，不以文字声量替代复算。
- **外部模型第二意见**负责攻击推理链，不直接增加独立事实。
- **最终 Skill**负责把上述结果组织成可审计的证据关系和行动成熟度。

对私人记忆或内部文档的核验，还要注意范围与隐私：搜索范围必须显式，私人内容不因检索方便而外发。

## 十、一句话操作纲领

> **先把说法拆成主张，再沿不同机制找证据；追溯原始出处、去掉伪多源、主动寻找反证；保留不能解释的矛盾，最后给出带证据缺口、证伪条件和行动边界的暂时最佳结论。**

这套方法的价值不是让人永远正确，而是让每一次判断都知道：**自己凭什么这样判断、哪一步还没验证、出现什么新证据就应该改判。**
