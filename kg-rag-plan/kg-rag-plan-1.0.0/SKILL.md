# 知识图谱 RAG 落地方案

## 这个 skill 解决什么

企业要做知识库问答，普通向量 RAG（Naive RAG）在多跳关系推理上会断链：问「A 产品的故障码 B 对应哪个部门的哪个流程」时，纯向量检索只能命中零散片段，拼不出关系。

知识图谱 RAG（KG-RAG）用 LightRAG 从文档抽取实体与关系建图，检索时图谱 + 向量双路召回，能走多跳。但它不是「装个库就完事」——**落地失败几乎都发生在四个地方**：没有评估集就开始开发、实体消歧不做导致图谱碎片化、文档更新把图谱搞腐化、权限被多跳穿透。

本 skill 把这些坑固化成流程和卡点，按你的数据量分档输出可执行方案。

## 使用方式

### 第一步：收集三个参数

必须先问清楚（缺一个就停下来问，不要猜）：

| 参数 | 为什么必须 |
|---|---|
| **文档份数** | 决定排期档位（8-10 / 10-12 / 12-14 周）和是否拆存储 |
| **场景** | 必须收敛到**一个**高频痛点（售后技术问答 / 合同条款审查 / 设备故障诊断），拒绝「全公司通用知识库」 |
| **密级与权限** | 有多密级就必须做图级权限穿透防护，否则方案不成立 |

### 第二步：跑分档脚本

```bash
python scripts/plan.py --docs 3000 --scene "售后技术问答" --multi-level-security
```

输出：排期档位、里程碑日期、存储模式建议（极简 PG 三合一 / 标准 Neo4j+Milvus）、成本区间、强制卡点清单。

不带参数时脚本进入问答模式，逐项问。

### 第三步：按六阶段执行

读 `references/phases.md` 拿每个阶段的步骤表、产出物、卡点。**卡点是硬门禁，不是建议**：

- 阶段 0 黄金评估集未通过评审 → **禁止进入阶段 1**
- 解析表格错乱率 > 5% → 先修解析，垃圾进 = 垃圾图谱出
- 实体重复率 > 8% → 调消歧管线或换更强抽取模型
- Context Recall < 0.80 → 按固定排查顺序，不要乱调参数

### 第四步：六项工程设计不能省

读 `references/engineering.md`。这六项是 KG-RAG 区别于 Naive RAG 的地方，也是绝大多数项目翻车的地方：

1. **实体消歧**（头号难题）：字典精确匹配 + LLM 兜底合并，重复率 < 8%
2. **图谱生命周期**：增/改/删三种操作分别处理，更新要「删旧子图再重抽」而非追加
3. **权限穿透防护**：检索层路径剪枝 + 生成层权限注入，必须测跨权限多跳攻击
4. **分级检索路由**：默认 Local 不是 Mix，预计 P95 从 8s 降到 3-5s
5. **成本控制**：先小批量实测单耗再外推，抽取模型不许降级
6. **版本锁定**：fork LightRAG，不跟最新

## 三条军规（写进方案里，不要删）

1. **抽取 LLM 不许省钱** —— 建图质量决定上限，弱模型建的图救不回来
2. **没有评估集不许开发** —— 评估集必须先于代码存在
3. **检索不到就拒答，永不编造** —— 拒答准确率是验收指标，不是兜底

## 输出什么

默认输出一份 Markdown 方案，包含：

- 场景定义与验收指标（含拒答准确率、P95 延迟）
- 六阶段实施计划（步骤 / 产出物 / 负责角色 / 卡点）
- 里程碑验收总表（M1-M5 及时间点）
- 存储模式与硬件规格（按档位）
- 成本预估表（LLM / Embedding / Rerank 分别计量）
- 风险矩阵（等级 / 对策 / 对应章节）

`--json` 输出机读版，便于塞进项目管理系统。

## 边界（做不到的事，明确说）

- **不代跑建图**。本 skill 产出方案，不执行 LightRAG 抽取；抽取要真文档和真 API key。
- **不估算没给的数据**。文档量、场景、密级必须用户提供；缺了就问，不编。
- **成本是区间不是承诺**。成本按「每 100 万字消耗数百万 token」的经验值外推，实际以阶段 2.1 小批量实测为准。方案里必须写这句。
- **不保证 RAGAS 分数**。验收线是目标，能否达到取决于数据质量和调优。

## 常见误用

| 误用 | 后果 | 正确做法 |
|---|---|---|
| 跳过阶段 0 直接建图 | 无法判断好坏，上线即事故 | 先做 200+ QA 评估集 |
| 默认用 Mix 模式 | P95 延迟 8s+，用户跑掉 | 默认 Local，低置信升级 |
| 文档更新直接追加 | 新旧实体矛盾，图谱腐化 | 删旧子图再重抽 |
| 抽取模型降级省钱 | 图谱质量塌方 | 抽取模型是红线，不许降级 |
| 只测正常问答 | 权限被多跳穿透 | 必须加跨权限攻击用例 |
