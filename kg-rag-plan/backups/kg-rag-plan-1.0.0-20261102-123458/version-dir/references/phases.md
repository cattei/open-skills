# 六阶段实施计划（含步骤、产出物与卡点）

> 周期按数据量分档：< 1000 份 → 8-10 周 ｜ 1000-5000 份 → 10-12 周 ｜ > 5000 份 → 12-14 周（阶段 2 拆为 2a+2b）。

## 阶段 0：场景定义与评估集建设（第 1~2 周）

> 定位：明确"做什么、做到什么程度算成功"。**评估集必须先于开发存在。**

| 步骤 | 动作 | 产出物 | 负责 |
|---|---|---|---|
| 0.1 场景收敛 | 选定**一个**高频痛点场景（售后技术问答 / 合同条款审查 / 设备故障诊断），拒绝"全公司通用知识库" | 场景定义书 | 业务负责人 |
| 0.2 数据盘点 | 清点文档来源（格式/数量/更新频率/密级），识别脏数据 | 数据资产清单 + 准入规则 | 业务 + 数据 |
| 0.3 问题收集 | 从工单/群聊/搜索日志收集 **150~300 条真实问题**。分布：事实型 40% / 多条件型 30% / 多跳型 20% / 库外问题 10% | 原始问题集 | 业务专家 |
| 0.4 对抗用例补充 | 额外收集：跨权限探测 / 时间敏感 / 歧义实体 / 组合多跳攻击 | 对抗用例集 | 安全 + 业务 |
| 0.5 标注黄金答案 | 业务专家逐条撰写标准答案 + 标注出处文档段落 | **黄金评估集 v1**（200+ QA 对） | 业务专家 |
| 0.6 定义验收指标 | Faithfulness ≥ 0.95 / Answer Relevancy ≥ 0.90 / Context Recall ≥ 0.85 / 拒答准确率 ≥ 0.90 / P95 延迟 < 8s | 验收标准文档 | 全员评审 |
| 0.7 环境就绪 | Docker Compose 拉起全栈，跑通官方 Demo；**用 10 万字文档压测 LightRAG 稳定性** | 可用测试环境 + 压测报告 | 工程 |

**卡点**：黄金评估集未通过评审 → **禁止进入阶段 1**。

**库外问题占 10% 是刻意的**：用来测拒答准确率。全是能答的问题，测不出拒答能力。

---

## 阶段 1：数据治理与解析管线（第 2~4 周）

> 定位：把文档变成干净、结构化、可追溯的入库数据。

| 步骤 | 动作 | 产出物 |
|---|---|---|
| 1.1 解析管线搭建 | MinerU 部署；每类文档各抽 5 份试解析，检查：表格错乱 / 双栏串行 / 页眉页脚混入 / OCR 准确率 | 解析管线 + 质量报告 |
| 1.2 清洗规则制定 | 去页眉页脚/水印/目录页；过期文档下线；敏感信息脱敏 | 清洗规则脚本 |
| 1.3 元数据规范 | 每份文档打标：`部门 / 文档类型 / 生效日期 / 密级 / 产品线` | 元数据 Schema |
| 1.4 小批量试建图 | 选 50~100 份核心文档入 LightRAG，**引入实体消歧管线** | 首版知识图谱 |
| 1.5 图谱质量抽检 | WebUI 人工检查：实体重复率 / 关系乱连 / 关键实体遗漏，每类文档抽检 ≥ 20 个实体 | 质检报告 + Prompt 调优记录 |
| 1.6 基线对比 | 同一评估集跑 Naive RAG（纯向量）vs LightRAG，RAGAS 打分 | 基线评估报告 |

**卡点**：
- 解析表格错乱率 > 5% → 调 MinerU 参数或换解析策略（**垃圾进 = 垃圾图谱出**）
- 实体重复率 > 8% → 调消歧管线 / 换更强抽取 LLM

**1.6 基线对比不能省**：没有 Naive RAG 基线，就无法证明 KG-RAG 值这个复杂度。很多项目在这一步发现纯向量就够了。

## 阶段 2：全量建图与检索调优（第 4~6 周，大档拆 2a+2b）

> 定位：全量数据入图，检索指标达到验收线。

| 步骤 | 动作 | 产出物 |
|---|---|---|
| 2.1 成本与容量预估 | 小批量实测 LLM 单耗 → 外推全量成本；预估向量数/图节点数 → 判断是否需拆分存储 | 成本预估表 + 容量规划 |
| 2.2 全量入图 | 分批入库（每批 500 份），失败重试，LightRAG 缓存保证断点续传 | 完整知识图谱 |
| 2.3 检索路由配置 | **Query 理解层**（意图识别+实体标注+改写+多轮）→ **默认 Local**，低置信升级 Mix，全局归纳走 Global | 路由策略 |
| 2.4 调优迭代 | 一次只改一个变量：top_k / chunk 大小 / Rerank 开关与阈值 / Query 改写 Prompt / 实体合并策略 | 调优实验记录表 |
| 2.5 权限过滤验证 | 按用户角色测试 metadata 过滤 + **跨权限多跳攻击用例** | 权限测试报告 |
| 2.6 增量更新管道 | T+1 自动管道覆盖**增/改/删**三种场景；定时扫描 → MinerU 解析 → LightRAG 增量/更新/删除 | 自动化数据管道 |
| 2.7 图谱版本化 | 每次大批量入图前做 Neo4j graph dump / backup，支持 restore | 图谱快照机制 |
| 2.8 中期评估 | RAGAS 全指标评估，**必须达到阶段 0 验收线** | 中期评估报告 |

**卡点**：Context Recall < 0.80 → 排查顺序：图谱缺关系（补数据）→ 分块过大（调小）→ Embedding 不适配 → 检索参数（最后调）。

**2.4 一次只改一个变量**：同时改三个参数，分数涨了也不知道是谁的功劳，跌了也不知道是谁的锅。

---

## 阶段 3：应用集成与可观测（第 6~7 周）

> 定位：接入业务系统，建立全链路可观测。

| 步骤 | 动作 | 产出物 |
|---|---|---|
| 3.1 API 集成 | LightRAG Server REST API 接入目标系统（企微/钉钉机器人、内部门户、工单系统） | 应用集成 |
| 3.2 交互设计 | ① 流式输出 ② 答案附引用来源（文档名+段落，可点击跳转）③ 图谱可视化入口 ④ 点赞/点踩按钮 | 前端功能 |
| 3.3 拒答机制 | 检索置信度低于阈值 → 明确回答"未找到相关信息"，**严禁编造**；记录该问题作为数据缺口线索 | 拒答策略 |
| 3.4 Langfuse 接入 | 全链路 Tracing：Query → 检索结果 → 图谱命中路径 → LLM 输入输出 → 耗时/token；点踩自动关联 trace | 可观测体系 |
| 3.5 语义缓存 | 高频相似问题命中缓存直接返回，降本 + 降延迟 | 缓存配置 |

## 阶段 4：影子运行与灰度上线（第 7~9 周）

> 定位：安全上线，随时可回退。

| 步骤 | 动作 | 通过标准 |
|---|---|---|
| 4.1 影子模式（1 周） | 线上真实流量双写：用户看旧系统答案，同时记录新系统答案，**只观察不展示**；每天复盘 20 条差异 case | 无 P0 级错误答案 |
| 4.2 灰度 5%（3 天） | 选取一个部门开放；监控错误率/点踩率/延迟/LLM 成本 | 点踩率 < 10% |
| 4.3 灰度 30%（1 周） | 扩大范围；收集真实用户新问题 → 补充评估集 | 指标稳定不劣化 |
| 4.4 全量上线 | 100% 开放；旧系统保留 1 个月作为回退方案 | 验收指标全部达标 |

**回退预案**：任意阶段出现严重幻觉/错误指引 → 1 小时内切回旧系统 → Langfuse 定位根因 → 修复后重新灰度。

---

## 阶段 5：持续运营闭环（长期）

> 定位：周级 bad case 闭环，持续优化。

| 机制 | 频率 | 动作 |
|---|---|---|
| Bad case 复盘 | 每周 | Langfuse 点踩记录**自动聚类** → 每类关联 RAGAS 指标维度 → 生成修复建议草稿 → 人确认后执行 |
| 归因分类修复 | 每周 | ① 图谱缺实体/关系 → 补文档或调抽取 Prompt ② 检索没召回 → 调 top_k/Rerank ③ 召回了但生成错 → 调生成 Prompt ④ 知识库确实没有 → 反馈业务补数据 |
| 评估集滚动更新 | 每两周 | 真实答错问题标注后加入黄金集，**每次系统变更必须跑全量回归** |
| 图谱健康巡检 | 每月 | WebUI 抽查实体重复率/孤立节点/错误关系；清理过期文档对应子图 |
| 成本与性能报告 | 每月 | token 消耗 / 缓存命中率 / P95 延迟趋势 |

## 里程碑总表

| 里程碑 | 时间 | 验收标准 |
|---|---|---|
| **M1** 评估集就绪 | 第 2 周末 | 200+ 标注 QA 对（含对抗用例），评审通过 |
| **M2** 小样本质检通过 | 第 4 周末 | 解析表格错乱率 < 5%，实体重复率 < 8%，优于 Naive RAG 基线 |
| **M3** 检索达标 | 第 6 周末 | RAGAS 全指标达验收线，增/改/删管道跑通，图谱版本化就绪 |
| **M4** 应用可用 | 第 7 周末 | API + 引用溯源 + 拒答 + Tracing + 权限防护全部就绪 |
| **M5** 全量上线 | 第 9 周末 | 灰度期间点踩率 < 10%，无 P0 错误 |
