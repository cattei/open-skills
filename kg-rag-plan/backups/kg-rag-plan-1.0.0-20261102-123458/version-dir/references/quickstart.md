# 知识图谱 RAG 落地方案 —— 快速上手

## 一分钟

```bash
# 给参数，直接出方案
python scripts/plan.py --docs 3000 --scene "售后技术问答" --multi-level-security

# 机读版，塞进项目管理系统
python scripts/plan.py --json --docs 800 --scene "合同条款审查"
```

不带 `--docs` / `--scene` 时进入问答模式逐项问。脚本化调用请加 `--no-ask`，避免挂起等输入。

## 三个参数

| 参数 | 作用 | 不填的后果 |
|---|---|---|
| `--docs` | 文档份数，决定排期档位与存储模式 | 无法分档 |
| `--scene` | 必须收敛到**一个**高频痛点 | 方案会退化成「通用知识库」，必然失败 |
| `--multi-level-security` | 有多密级就必须做权限穿透防护 | 漏做会导致越权泄露 |

档位对照：

| 文档数 | 档位 | 总周期 |
|---|---|---|
| < 1000 | 小规模 | 约 9 周 |
| 1000 - 5000 | 中规模 | 约 11 周 |
| > 5000 | 大规模 | 约 13 周 |

## 输出结构

脚本产出 Markdown 方案，八节：

1. 排期（六阶段起止周 + 日期）
2. 里程碑验收（M1-M5）
3. 验收指标（含拒答准确率、P95 延迟）
4. 存储与硬件（极简 / 标准）
5. 成本预估（建图 token 与人民币区间）
6. 硬门禁（六条）
7. 三条军规
8. 多密级附加要求（仅 `--multi-level-security` 时出现）

## 成本公式

```
建图 token ≈ 文档总字数 / 100万 × 200万~500万
建图成本   ≈ 建图 token / 1000 × 模型单价(¥/千token)
```

按 1 万字/份、¥0.002/千 token 粗估：

| 文档数 | 建图成本 |
|---|---|
| 500 | ¥20 ~ ¥50 |
| 1000 | ¥40 ~ ¥100 |
| 3000 | ¥120 ~ ¥300 |
| 5000 | ¥200 ~ ¥500 |

**这是区间不是报价**。方案里必须写「实际以阶段 2.1 小批量实测为准」。Embedding / Rerank 另计。

## 常见问题

**Q：能不能跳过阶段 0 直接建图？**
不能。没有评估集就无法判断好坏，上线即事故。这是军规第二条。

**Q：Mix 模式效果最好，为什么不默认？**
延迟 P95 8s+，用户会跑掉。约 40% 是简单事实型问题，Local 就够了，低置信再升级 Mix。

**Q：文档更新直接追加不行吗？**
不行。会造成新旧实体矛盾（旧价格和新价格都留在图谱里），必须删旧子图重抽。

**Q：抽取能不能用小模型省钱？**
不能。抽取模型决定图谱质量上限，建图后无法补救。这是军规第一条。

**Q：能不能不用 Docker？**
源方案基于 Docker Compose 编排。若受限，最小可行是单容器 PostgreSQL 三合一（pgvector + AGE）跑极简模式。
